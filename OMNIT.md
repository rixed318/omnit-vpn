# OMNIT desktop network layer

OMNIT is an open, user-controlled fork of Throne for a direct-first Kubuntu
workstation. It keeps ordinary traffic on the physical connection and sends
only selected services through a proxy.

## Current bridge architecture

```text
applications and Waydroid
          |
          v
OMNIT sing-box TUN + split DNS
          |-- unmatched traffic ------------> DIRECT
          `-- selected/blocked services -----> selected OMNIT Xray outbound
                                                    |
                                                    `-> VPN server
```

HAPP is no longer a runtime dependency. OMNIT imports the owner's protected
subscription into its private application database and starts the selected
full Xray configuration through ThroneCore. The repository contains no
subscription token, HWID, server credential or generated private database.

## Default policy

- Final route: `direct`.
- Proxy: Russian blocked-site lists and Re:filter plus explicitly selected
  services such as OpenAI/ChatGPT/Codex, Grok/xAI, YouTube, Instagram,
  Facebook, TikTok, X/Twitter, Discord, Spotify, GitHub, Google Play/FCM, and
  SourceForge.
- Direct overrides: specifically selected Russian services and the maintained
  `ru-available-only-inside` rule set run before broad proxy lists.
- Remote DNS: Cloudflare DoH through the proxy for proxied domains.
- Direct DNS: the local system resolver for ordinary domains and proxy-server
  bootstrap.
- Private/LAN ranges: bypassed so local devices and container bridges remain
  reachable.
- Remote rule sets: downloaded through the proxy, so initial bootstrap does
  not depend on GitHub/jsDelivr being reachable directly.

## Built components

- `build/Throne` — Qt 6 desktop client.
- `build/ThroneCore` — sing-box 1.13.16 with Xray-core 26.7.28 support.

## Owner-local control protocol

The existing single-instance `QLocalServer` also exposes
`OMNIT-CONTROL/1 <json>\n` to the same desktop owner. It is not a network API,
does not listen on TCP, and the socket uses `UserAccessOption`. Version 1
supports status, connect/disconnect/toggle, TUN mode, safe server and route
selection, the public 284-service catalog plus three automatic rules, applying
service choices, activating or refreshing a subscription, restarting the GUI,
and raising the advanced windows. A newly supplied HTTPS subscription URL
crosses the owner-only socket once and is persisted only by the VPN process; it
is never echoed in a response. Responses intentionally omit subscription URLs,
HWID, credentials and raw proxy configurations. This is the stable boundary
used by the OMNIT Control Center; the Control Center does not duplicate the VPN
database.

Control requests and saved-state restoration never open privilege dialogs.
When TUN or privileged DNS needs elevation, the control API returns
`ok: false`, `accepted: false`, `error: "core_privileges_required"`; the owner
can grant privileges through the VPN application's own controls. Repeated or
disconnected background requests cannot accumulate dialogs or replay a request.
Interactive elevation permits one dialog/command sequence at a time and stops
if the ownership change is declined or fails.

The same unattended behavior covers profile configuration failures, worker-side
core start/stop errors and timeout prompts. Immediate invalid configurations
return `invalid_profile_config`; later core failures appear as
`core_start_failed`, `core_stop_failed` or `core_unavailable` in status, without
exposing raw configuration details. The background mode follows asynchronous
profile ranking and restarts; explicit native UI actions keep their dialogs.

Linux regression check: `python3 script/test_control_privileges.py --binary
build/Throne`. It uses temporary databases and an unprivileged copy of the core
to exercise repeated/concurrent requests, disconnected clients, saved TUN,
privileged DNS, missing routes, invalid Warp and asynchronous core rejection
without changing the owner's network configuration.

The local branch is `omnit`; the original project is retained as the
`upstream` Git remote.

## Service dataset integration

The original JSON linked from `~/Downloads/deep-research-report.md` was not
actually downloaded and its private `sandbox:` URL could not be recovered from
Chrome. OMNIT therefore carries an independently reproducible catalog at
`res/omnit-services.json`, generated by
`script/generate_omnit_services.py` from the recorded
`v2fly/domain-list-community` commit plus narrow reviewed first-party
overrides. It is not represented as byte-identical to the missing report file.

The current catalog has 284 unique services, 24 categories, 54 RU proxy
defaults, 230 RU direct defaults and 47 security-sensitive entries. Exact
domain ownership is unique across switches; empty services, URLs, wildcards
and dangerous broad infrastructure suffixes are rejected during generation.
Three automatic rules (RU inside-only, RU blocked and Re:filter) are appended
by the application. The UI provides search and warns on sensitive services.

`Проверка IP и утечек` is a normal owner-controlled switch in the Security
category and defaults to Proxy. It owns reviewed IP/DNS/WebRTC/fingerprint
checker domains. OMNIT's two public-IP cards use dedicated loopback-only
inbounds: port 2081 is always VPN and port 2082 is always Direct, so diagnostic
truth does not depend on that switch or on the selected whitelist.

Rules are compiled in this order:

1. explicit user overrides;
2. specific service domain/process rules;
3. RU inside-only and security-sensitive direct rules;
4. broad RU blocked/Re:filter proxy rules;
5. default direct.
